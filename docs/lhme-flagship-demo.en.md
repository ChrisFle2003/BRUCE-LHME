# LHME Flagship Demo — Virtual Rule Values with Sparse Overrides

This text-based flagship demo presents the central LHME use case: a large,
logically addressable value space is generated by a deterministic rule. Only
real local deviations are stored. A bounded streaming query filters by a
modular value first and performs the expensive Exact evaluation only for the
remaining addresses.

The demo is for people who want to see the difference between a virtual value
space and a materialized table. It uses only the existing `PowerOffset` formula,
`FormulaOverrideStore`, and its Store-bound streaming query.

## Requirements

- CMake 3.25 or later
- A C++20 compiler with thread support
- Boost headers including `boost/multiprecision/cpp_int.hpp`

Run these commands from the repository root. They build only the demo target;
tests, tools, and benchmarks are not required.

```bash
cmake -S . -B out/build/lhme-flagship-demo -DBRUCE_BUILD_EXAMPLES=ON
cmake --build out/build/lhme-flagship-demo --target lhme_flagship_demo --parallel 2
./out/build/lhme-flagship-demo/lhme_flagship_demo \
  --snapshot /tmp/lhme-flagship-demo.snapshot
```

`--snapshot` is required. Its parent directory must already exist and be
writable. The demo writes the snapshot there and then loads it again.

## What the demo shows

### 1. A rule instead of a full table

The registered rule is:

```text
PowerOffset(base=2, scale=100, version=1)
value(index) = 100 * (2^index - 1)
```

Address `1_000_000`, for example, is logically valid without storing one
million values. The demo requests that address in `Metric` mode. Its result is
`Computed` with bit length `1_000_007`; no exact `BigInt` is materialized.

### 2. Three persistent local corrections

The demo stores exactly these overrides:

| Address | Effective value | Source |
| ---: | ---: | --- |
| 10 | -40 | `Override` |
| 777 | 17 | `Override` |
| 999 | 0 | `Override` |

A point query for address 10 consequently returns `Override -40`. Address 11
has no correction and returns `Computed 204700`. Source is part of each Store
result and every retained streaming candidate.

### 3. Bounded streaming with a modular prefilter before Exact

The demo then queries range `0..1023` with these options:

| Setting | Value |
| --- | --- |
| Filter | effective value `mod 17 == 11` |
| Retention | `TopK` |
| Maximum candidates | 4 |
| Retention bytes | 4 KiB |
| Address budget | 1,024 |

Retention bytes are a deterministic estimate for deliberately retained
candidates and their results. They are **not** a hard process-memory limit and
do not bound thread stacks or temporary allocations during evaluation.

The modular filter operates on the **effective** value, including a possible
override. Only matching addresses are then evaluated exactly. The expected
counters are:

```text
stream checked  | 1024
stream filtered | 896
stream exact    | 128
stream retained | 4
computed exact delta | 127
```

The computed Exact delta is smaller because address 10 is an override and does
not require a computed Exact evaluation. The four retained candidates show
their origin:

```text
candidate 2  | Computed 300
candidate 10 | Override -40
candidate 18 | Computed 26214300
candidate 26 | Computed 6710886300
```

The demo also deliberately requests a range of 1,025 addresses. The address
budget rejects it with `BudgetExceeded` before Exact work begins.

## Override capacity: rejection, not eviction

`FormulaOverrideStoreConfig` can limit correction count, total deterministically
accounted payload, and the size of an individual override value. Payload is the
canonical stored override key plus the magnitude bytes of its `BigInt`; zero
uses one value byte. This is a Store capacity contract, not a process-memory
measurement.

The default configuration remains unlimited for compatibility. With a
configured limit, a new or replacement override that would exceed it returns
`BudgetExceeded`; an existing override stays unchanged. LHME deliberately does
not evict business corrections. A valid snapshot that does not fit its target
Store returns `CapacityExceeded` and leaves the target's current contents
unchanged.

## Snapshot: rule binding and corrections, not a full table

The snapshot stores sparse override records with their Formula or Technique
binding, address, value, and an integrity check. It stores neither computed
values for other logical addresses nor a materialized table.

For reload, the demo registers the same `PowerOffset` formula in a new Engine,
loads the snapshot into a new Store, and checks address 10 again. The reported
snapshot byte count is an observation of that file, not a fixed-format-size
promise.

## Cooperative cancellation in Store streaming

Store-bound streaming accepts a request-local cancellation flag or signal.
Cancellation is cooperative and observed at stream boundaries:

- before a tile is dispatched;
- between addresses or tiles; and
- before retained results are published.

When cancellation is observed at one of these boundaries, the query returns
`Cancelled` and `retained_candidates` is empty. A Formula or Technique
evaluation already in progress is not preempted, so its duration bounds
cancellation responsiveness.

## Non-goals

This demo is deliberately not a database, persistent table store, network
service, GUI, GGUF importer or rewriter, model-inference runtime, or LLM
runtime. It demonstrates local, deterministic, bounded reconstruction of rule
values with a small set of explicit corrections.
